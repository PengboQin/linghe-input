## 执行方式

1. 发现问题时先给登记号，保留最小合成输入、发生位置、预期规则和实际结果。无法复现仍登记为“用户报告”，不要先定根因。
2. 分清共享核心、公共词库/模型、原生会话、候选UI/触摸、持久化/同步、安装器/系统适配的责任层。共同现象不等于共同根因；公共修复由主维护者协调唯一 `core/`，各端处理自身适配。
3. 每个修复带一组可迁移的合成用例。正在开发的其他端同时补验；暂时不具备条件的端写明阻塞和恢复入口，不宣称已对齐。
4. 一批稳定候选中集中执行相关用例，复用现有设备、构建目录和证据；没有新增改动或证据不反复跑全量。已有数据原地保留，不为回归卸载清库。
5. “源码实现 / 构建 / 安装 / 合成验证 / 真实系统宿主 / 用户接受”独立记录。源码同源、编译或截图通过均不能替代其他端的实际行为。

## CP-001：九键重复按键专项

原始案例是 `444`，不得先转换为某组字母后丢失原码，也不指定一个唯一正确词。用户说“把4对应的三个字符直接显示出来”，目前尚不清楚出现在候选区、组合标记区还是已提交正文，须先复现分层记录。历史 iOS47有重复简拼修复记录，仅作定位线索，不关闭当前报告。

### 合成用例

| 用例 | 操作 | 必须观察 |
| --- | --- | --- |
| R1 | 分别输入 `4`、`44`、`444`、`4444`；每轮从空组合开始 | 原始数字码逐键保留；实际分段/候选变化；有无未经确认的字母替代或正文提交 |
| R2 | 在固定词库/模型版本的隔离资料中，覆盖有匹配和无匹配状态 | 先记录实际召回，不能为让测试通过假设 `444` 必须无词；无匹配原因及兜底路径可解释 |
| R3 | 对R1各前缀追加可组成有效音节的合成尾码，例如 `426`，同时设一组实际无匹配对照 | 组合原码、分段和可消费范围；追加后能重新召回，不被字母兜底或空结果锁死 |
| R4 | 候选存在时先选择一个前缀，再继续重复键/追加尾码 | 已选前缀不重写；只消费实际覆盖的原码，尾码不丢失、不重复 |
| R5 | 从 `4444` 单步删除到空，再重新输入；另测清空按钮 | 回退后的原码/候选一致；旧任务不复活；正文不被隐式补入 |
| R6 | 快速连按与慢速逐按；候选加载/排序更新前后点选、展开/收起 | 记录每次输入/请求/快照代际，显示与点选同一候选，不因刷新误选 |
| R7 | 有未选组合时失焦、切其他IME后切回，再继续输入/删除 | 根据该端既有会话规则恢复或结束组合；无旧候选回灌、重复上屏或残留拼音 |
| R8 | 显式数字/英文模式、显式原文提交与九键拼音模式对照 | 允许的字面提交仍可用；修复不得吞数字、英文、标点，也不得把未选字母伪装成中文候选 |

有匹配、无匹配、部分选词三类在同一份fixture中分别保留。用例只使用隔离合成资料，不通过改动真实个人词库制造条件。

### 四层输出必须分开

- **候选区**：每个可见候选的文本、稳定ID、名次、覆盖原码范围、来源/过滤和快照代际。
- **组合/标记文本**：仍待确认的原码或展示文字、范围及更新事件；不能因看见字母就认定已上屏。
- **提交正文**：实际提交事件、文本、消费范围、触发动作、提交次数；不能只看候选UI推断宿主收到。
- **显式字面上屏**：用户选择数字/英文模式、Enter/原文动作等具体触发。其行为与无匹配时自动替换必须区分。

最低验收规则是原输入可追溯、无未经确认的提交、明确选择只提交一次、已选前缀与尾码完整、过期结果不生效。无匹配时的候选展示策略先对照现有产品契约；契约不清时列为待定，不能在修Bug时擅自设定唯一正确词或转换规则。

桌面端若没有九键UI，九键触控用例填 `N/A（无九键UI）`；仍执行共享核心九键fixture，以及26键重复字母/无匹配、部分选词、删除、失焦、显式原文提交边界。`N/A` 不能用来跳过共享核心或桌面提交适配。
