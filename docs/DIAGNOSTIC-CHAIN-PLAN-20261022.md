# 召回、排序与误选诊断链路开发清单

> 本批实施结构：字段定版与精确 JSON 以 [INPUT-DECISION-DIAGNOSTICS-V1-20261022.md](INPUT-DECISION-DIAGNOSTICS-V1-20261022.md) 和共享合成 fixture 为准。保留旧 `org.linghe.input.v1` 原码字段，将有界决策链追加为同一默认关闭 provider 下的 `org.linghe.decision.v1`；普通输出只携 `org.linghe.decision-link.v1` 纯 ID。下文 phase/candidate_generation 等建议语义分别通过 stage/state_id/snapshot_id 映射，尚未支持的字段保留后续任务，不能声称已实收。`published_subset` 是发布预览而非真实曝光；总数未知省略 total_count，快照外选词使用独立 selected_candidate。默认授权、队列预留与撤权围栏保持不变。

日期：2026-10-22（America/Los_Angeles）。状态：开发计划与字段合同建议；尚未因本文修改产品、启用采集、部署或完成跨端验收。

## 目标与证据

先把一次组合的「原码 → 候选生成 → 实际可见 → 选择动作 → 上屏观察 → 明确纠正」关联起来，让缺词、排名靠后、候选未曝光、点选错位及提交失败能分别定位。复用现有独立默认关闭的 `ime.diagnostic.v1`，不新建全局键盘监控，也不将已有输入提交/剪贴板授权解释为过程采集授权。

来源：维护侧《灵鹤输入法融合诊断-20261022》（本地原报告位于 `维护侧私有诊断报告（原始记录不公开）`）、[既有过程诊断合同](INPUT-DIAGNOSTICS-V1-20261021.md)、[来源场景合同](ACTIVITY-SOURCE-CONTEXT-20261020.md)。诊断快照中输入过程记录为 0；这只说明该窗口未观测到，不能判定是用户未输入、未授权、未接线或版本未送达。版本、布局及公开机型元数据已开始收集，应补一致性和缺失原因，避免重新实现一套并行字段。

优先处理的线索：候选按下后刷新/停顿重排、点选无响应、长拼音部分选词后的余码、九键同码及重复键。它们是待复现问题，尚无可计算的发生率或统一根因。Android 旧版词库准备/切换异常已有局部修复证据，应做回归，不能继续当作确定未修复问题。

公共词频底座与显式拼音词典已有规模，暂不整体扩词或调权。显式单字读音覆盖缺口不等于终端不能输入；应以固定词库版本的实际召回验证决定补词/补音。词库审计、学习收益和网络成本列后续任务，先交付本清单的 P0。

## P0：本批必须完成的最小闭环

- [ ] **P0-1 合同与能力核对**：逐端核对既有诊断事件是否实际接线、版本与能力；列出支持/不支持/未验证，冻结下方追加字段、枚举、长度界限及旧读者兼容样例。
- [ ] **P0-2 关联与候选观测**：绑定组合、修订、请求、候选代次、曝光和选择；所有迟到回调校验输入会话/编辑器代际，不能把上一输入框的结果挂到新组合。
- [ ] **P0-3 按下到提交闭环**：手机记录按下时目标与松手命中；桌面记录鼠标/数字/空格/回车等选择目标。输出记录与决策通过 ID 关联，不以时间接近拼接。部分选词记录消耗区间与余码。
- [ ] **P0-4 版本与计时**：同一输入时钟域记录查询、显示、动作和提交阶段；固定实际采用的核心/词库/模型版本，补覆盖缺口与截断状态。
- [ ] **P0-5 有界离线回放**：用合成原码、已知目标和固定资源运行召回/排序/交互回放，覆盖下方 C01–C10；不使用真实私人正文做公开 fixture。
- [ ] **P0-6 端到端合成核收**：经既有签名 ingest → query → export 验证新字段与关联不丢失，旧读者仍分开统计诊断/提交/剪贴板。NAS 侧只读核对，不改拉取器、回执或处理状态。
- [ ] **P0-7 分端交付**：源码、构建、安装、系统宿主验证、实际核收、用户体验分别登记；未完成的端明确挂起原因。不开真实过程采集来凑验收，默认关闭状态本身也要验证。

P0 完成标准：同一个合成失败能被明确归为「指定范围内未召回 / 召回后排名问题 / 未曝光 / 选择目标与提交不一致 / 提交未确认 / 证据不足」之一；不存在依赖时间邻近或候选文本猜 ID 的关联。验收同时证明诊断关闭、队列满和权限变化不妨碍正常输入。

首批采集档位限定为**组合决策摘要**：组合结束或部分选词时写有界摘要，携带原码/余码、该次选择实际引用的候选代次与曝光、选择目标、输出关联及阶段计时。未选择而取消也有结束摘要。不默认保存每个按键、每次重绘或所有中间候选；完整逐键/阶段序列只在单独说明的短时诊断窗口或合成回放中使用。候选全集枚举/目标搜索先留在离线回放，避免为了诊断拖慢日常输入。

## 事件合同与字段

继续使用现有 `source_import`、`source_kind=ime_diagnostic`、`commit_confirmation=not_applicable`；字段追加到现有 `extensions.org.linghe.input.v1`，加 `diagnostic_schema_revision` 区分本批能力。旧 `action`、`raw_before/raw_after`、`candidate_preview` 保持兼容，不把新字段复用为另一个含义。现有会话、编辑器代际、事件/安装/序列 ID 复用，不复制到互相矛盾的新字段。

下表是语义合同，实施时应在同一份 fixture 中冻结准确 JSON 结构；新增事件阶段放在 `phase`，旧 `action` 继续表示原输入动作。决定摘要及逐键明细都属于诊断 provider，均受独立授权约束。

| 字段组 | 最小字段 | 语义与边界 |
| --- | --- | --- |
| 能力与状态 | `diagnostic_schema_revision`、`capabilities`、`observation_status`、`unavailable_reason` | 记录哪些阶段受支持。`observed / unknown / not_applicable` 分开；未知不能按 0 或 false 汇总。能力不随上传时版本补写 |
| 组合身份 | `composition_id`、`revision`、`phase` | 输入法自建不含业务含义的随机 ID；同一编辑器内组合开始到结束，编辑/部分选词递增 revision；结束原因为 commit/cancel/clear/editor_change 等 |
| 请求与代次 | `query_id`、`candidate_generation_id`、`query_status` | 请求绑定组合修订与实际模型；结果 ready/empty/error/stale_discarded/cancelled 分开。`ready` 不代表已显示 |
| 原码与分段 | 复用 `raw_before/raw_after`，追加 `mode`、`selected_prefix`、`consumed_range`、`remaining_raw`、`end_reason` | 明确九键/26键/英文/数字/符号与自动纠错模式；区间以原码字符索引为单位，半开区间；前缀属于本组合，不读宿主周边正文。继续遵守现有 4 KiB 上限并显式报截断 |
| 候选身份与来源 | `candidate_id`、`absolute_rank`、`candidate_origin`、`match_kind`、`candidate_generation_id` | ID 至少在同一 generation 内稳定唯一；相同文本不同分词/读音路径不能合并为一个候选。零起始绝对排名在合同中固定，界面显示时再加 1；来源如公共/个人/云/纠错/续写 |
| 真实曝光 | `exposure_id`、`visible_candidate_ids`、`visible_rank_ranges`、`display_state`、`snapshot_complete`、`list_complete`、`total_count_status`、`total_count` | `snapshot_complete` 只说明本次可见集合是否完整；`list_complete` 另说明整个请求范围是否枚举结束。可滚动/展开候选仅在真正渲染可见后记曝光；数量未知省略数值并写 unknown，不强制枚举全集 |
| 选择动作 | `decision_id`、`selection_method`、`down_exposure_id`、`down_generation_id`、`down_candidate_id`、`up_candidate_id`、`resolved_candidate_id`、`cancel_reason` | touch/mouse/digit/space/enter/explicit_literal 等分开；取消也是有效结局。桌面无 touch 时标 not_applicable。允许产品按既定策略锁定或取消过期动作，不允许静默提交另一候选 |
| 提交关联 | `decision_id`、`selected_candidate_id`、`output_event_id`、`selection_commit_match`、`commit_observation` | 输出记录通过扩展反向携带 decision_id，或由摘要指向已分配输出事件 ID，选一种稳定关联方式。部分提交可一对多；无输出用 unknown/no_output_observed，不虚构失败。区分 insert_requested/editor_acknowledged，均非消息发送证明 |
| 版本指纹 | 复用 App version/build/layout/platform；追加 `core_revision`、`resource_manifest_hash`、`policy_hash`、`cloud_model_version/hash`、`local_overlay_revision` | 哈希使用公开资源/策略的规范清单，不哈希私人正文。记录实际被该请求使用的版本；未加载/不支持/未知分别标记。本地覆盖用不含正文的修订号，不公开个人词库哈希或内容 |
| 单调计时 | `clock_domain_id`、`key_received_us`、`query_start/end_us`、`displayed_us`、`down/up_us`、`commit_requested/ack_us` | 同一进程启动随机 clock_domain_id，不用系统设备标识；阶段时间统一单调微秒整数，无阶段则 unknown。跨域仅显式关联，不相减；墙钟与上传时间不用于键盘延迟 |
| 采样/缺口 | `sampling_policy_version`、`sampling_unit`、`sampling_probability`、`sampled`、`truncation_reason`；复用 coverage_gap 加 provider、reason、起止域/水位 | 以完整 composition 为采样单元，避免只留成功点击；概率和纳入规则可解释。缺口数仅在可证实时填，不能把一条 coverage_gap 当丢了一个字 |

### 候选曝光与召回不能混用

现有 `candidate_preview` 最多 5 项，是有界样本；未出现在其中只能判定「未观察」。P0 不因诊断扩成全词典候选日志：可见 ID 集合可分有界分片，每条关联同一 exposure_id，若仍超限就标不完整。候选正文仍沿用既有预览上限；ID 没有对应可核验的正文映射时也不能推断目标缺失。

召回和排名主要先通过**离线标注回放**判定：fixture 明确原码、目标、资源版本与枚举上限 K；额外报告 `enumeration_complete`、`search_scope`、`eligible_after_policy`。目标不在 Top K 但枚举未完时记「未在 K 内召回，全集未知」；仅在完整、明确范围内才可说未召回。目标被策略排除与根本无词条是两类原因。实时记录只在用户主动反馈并提供目标、且诊断授权覆盖时进行有界目标追踪，不能后台推断用户意图。

### 异步、部分选词与提交顺序

1. 输入 `nihao` 产生 revision 1/query A；改为 `nihaoma` 产生 revision 2/query B。A 晚到只能留下 stale_discarded 状态，不得刷新 B 的曝光。
2. 手机按下 exposure E 的候选 X；候选刷新到 E2 后松手。记录 down/up/resolved 三者及取消原因；提交 X 或取消应符合产品既定交互合同，不能提交无关联的 Y。键盘/鼠标选择遵循相同代次约束。
3. `nihaoshijie` 选择前缀「你好」后，记录消耗区间、余码 `shijie` 和 prefix decision/output 关系，保持 composition_id、递增 revision；不能把部分提交当全轮结束，也不能把余码误记成新输入。
4. 清空、失焦、换输入框、权限变化必须关闭或隔离旧组合，未完成回调不得连到下一编辑器。插入请求没有系统确认能力时记能力未知，不靠读回宿主正文补确认。

## 授权、性能与隐私验收

- 默认关闭继续有效，确认 UI 明示未选中/未发送拼音会被保存。不得继承输入提交、共享文本、云学习或剪贴板同意；关闭/离组/暂停/权限代际变化的在途数据按既有围栏处理。
- 仅记录本输入法拥有的组合与公开输入框元数据；secure 或未确认安全的字段排除。iOS 宿主身份未知是平台能力边界，不能用窗口标题、附近聊天、网址或其它键盘信息补齐。
- 沿用诊断达到本地事件/字节预算 75% 时停止、给输出/剪贴板预留空间的规则；失败丢弃不可阻塞打字。缺口/健康通知遵守现有 provider 与授权合同，不另开隐形采集通道。
- 不同步枚举全库、不在每次按键计算资源哈希；指纹在资源加载时计算/核验并缓存，请求绑定快照引用。日志入队异步、有界，队列满/磁盘失败/工作线程退出都能降级。
- 采样在组合开始时决定并保持整轮一致；采样外、触点摘要未采、上限截断、IPC 丢帧、采集关闭等有不同状态，不能混入准确率分母。
- 公开文档、Git、issue、fixture 仅合成原码/目标及协议字段；真实正文、真实组/设备标识与运营配置保留受限位置。正文哈希也不是匿名化方法。

## 合成回放与跨端验收案例

以下案例不声称当前实现通过；主维护者需为每端填入源码/构建/安装/系统宿主/核收证据。重复键问题应同时登记到跨端缺陷台账，修复某一端不代表其余端验收通过。

| ID | 合成操作 | 验收重点与可用证据 |
| --- | --- | --- |
| C01 | 26 键输入 `nihao`，固定目标「你好」 | 原码、查询、实际曝光、选择、输出同一链；固定核心/词库的 Top K/排名可回放 |
| C02 | 九键连续输入 `444`；再测 `44`、`4444`，停顿/删除/重输 | `444` 不保证无匹配，有无匹配以固定词库实际结果为准；无匹配时的展示与组合保留沿用既有产品合同。不能把每个 4 映射的字母串当中文候选或未经明确选择直接上屏。显式字面/英文模式另列，不能为修中文破坏合法字面输入 |
| C03 | 对 C01 人工注入候选迟到刷新，按下 X 后刷新、松手 | down/up/resolved 及 generation 可关联；旧候选被锁定或取消，不能变成 Y；取消无输出不计误选 |
| C04 | `nihao` → `nihaoma`，让前一请求晚于后一请求返回 | 旧结果丢弃，曝光属于当前 revision；重放可复现而非猜测停顿排序 |
| C05 | `nihaoshijie` 先选「你好」，再选择剩余部分 | prefix、consumed_range、remaining_raw 和两次输出关系完整；余码未丢、未重复提交 |
| C06 | 输入中清空/失焦/切输入框，再让旧回调返回 | 组合结束原因可见；editor_epoch 隔离，不能关联另一输入框 |
| C07 | 固定目标排在 Top5 之外，分别不展开/展开滚动 | 不展开时目标未观察；展开后曝光才成立；不能因旧 preview 无目标报告缺词 |
| C08 | 固定合成词，分别构造缺词、低排名、策略排除及日志截断 | 四类输出不同；仅范围完整时判断未召回，截断/未观测保持 unknown |
| C09 | 诊断关闭、关闭中有在途事件、队列饱和、工作线程/IPC 中断 | 新诊断数据不越权发出，代际围栏生效；原输入仍可用，缺口不虚构丢失字数 |
| C10 | 同一固定回放集切换模型/本地覆盖，再做系统宿主输入 | 请求绑定实际采用版本；输入中安全边界采用新模型；比较召回/排名，不能以版本下载成功证明精度提升 |

重复键按九键支持能力分端验证；不支持九键的桌面端登记 not_applicable，并验对应 26 键重复字符、空候选与显式字面提交路径。不得为了凑同一张表新增平台不需要的键盘模式。

Windows 用户已反馈新安装包也无法安装；这是当前独立交付阻塞，优先由该机上的 agent 取得可核验的错误再决定修法。它不阻塞其它端的合同、回放和接线。本批新增诊断候选实际安装并完成对应验收以前，其系统宿主与真实诊断核收保持未验；不倒写已完成的 054 原生输入验收为未验。

## 可交付的分析口径

首选命中率/MRR/召回@K只使用有明确目标、同一版本范围及足够候选观测的标注集；用户按空格不是首选正确的真值。点选一致率仅使用 down/resolved/output 完整的动作，取消单列。插入请求与编辑器确认分别报告。所有统计同时给出合格分母、未知/采样/截断/缺口数量；历史缺字段不回填猜测。

本计划落盘表示开发任务可审阅，不表示链路已完成或同意已开启。完成后由主维护者合并跨端证据、更新既有任务台账并按公开白名单审计更新 Git；产品代码与真实记录不因本文自动提交。
