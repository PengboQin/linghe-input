# Windows 长组合候选定位

用户明确反馈平台为Windows：短拼音正常，较长组合时候选框突然偏到屏幕左侧。未修改Mac或手机的定位代码。

## 已证实的源码路径

1. `TextService::updatePanel`已经将组合范围克隆并折叠到末端；不能把问题直接归因“取了整个组合的首矩形”。但`GetTextExt`失败或矩形高度无效后，旧代码无条件取宿主窗口外框左上方加16/40，制造与光标无关的锚点。
2. 原候选布局按整个显示器可用宽度测量，最大900逻辑像素。已用纯几何重现：1920物理像素/200%缩放，caret x=1040，长行1800像素，右边界clamp使候选左边变成120，偏移920像素。

## 本轮修复

候选布局先以caret右侧真实可用宽度为预算；靠右边缘不足一行最小可读宽度时，只允许该最小行向左避让。宽度仍由实际候选内容决定，不改字号、配色、候选数量或选词键义。

坐标失效路径已接入独立有限锚点策略：不造宿主左角坐标，仅同context/view/composition/epoch/DPI/host原点且仍有效焦点下复用最近验证点不超过200ms，不续期；空/clipped/失焦等清除，TSF只读布局回调刷新。旧定时消息、销毁代际、旧view晚销毁与已存在新view恢复均补围栏。41项策略ASan/UBSan及生产DLL交叉构建通过，不能代替实机TSF通过。

## 验证与现场边界

ASan/UBSan候选布局回归通过，包含旧920像素偏移的精确复现与新短/长宽度固定锚点、96–288 DPI真实右边缘、负坐标显示器、窄屏和命中区一致性。

PC原生Codex负责真实054短→长、换行、展开、窗口右移的复现；初轮合成宿主尚未复现突然到左侧，继续区分边界避让和坐标失效。尚未声明用户真实宿主根因已被完整确认，未安装新候选。

旧054包、真实组/归档/默认、运行后台保持。安装/修复/真实验收仅由PC本机执行；不从Mac操作Windows系统。主线公共core未改，Windows仍独立适配。
